# Obtenir un kubeconfig

Skyline affiche l’adresse de l’API Kubernetes dans le détail du cluster. La CLI assemble en plus une configuration utilisable par `kubectl`. Cette commande n’est exposée ni dans le détail ni dans les actions de cluster du fork. [Client Magnum de Skyline](https://github.com/armeldemarsac92/skyline-console/blob/5a8ca40e86cbcbacf725b38fc14ca5acbed1e19a/src/client/magnum/index.js).

| Commande `openstack coe …` | Requêtes Magnum | Résultat et couverture Skyline |
| --- | --- | --- |
| `cluster config <cluster>` | `GET /v1/clusters/{ident}` puis `GET /v1/clustertemplates/{uuid}`. Si TLS est actif, `GET /v1/certificates/{uuid}`, puis `POST /v1/certificates` en mode certificat. | Le client assemble et écrit le kubeconfig localement. Skyline affiche l’adresse API seule. |

## Construction sur le poste de l’utilisateur

- `--use-certificate` est le mode par défaut. Si TLS est actif, le client génère une nouvelle clé privée RSA et un CSR sur le poste, avec `CN=admin` et `O=system:masters`. Magnum reçoit le CSR et renvoie le certificat signé. La clé privée reste sur le poste. Le fichier `config` contient la clé privée, le certificat client et la CA encodés en base64. Le base64 conserve ces données en clair après décodage. Les fichiers sont ouverts en écriture sans permissions explicites dans le client épinglé. La protection effective dépend donc des permissions préexistantes et de l’`umask`. [`ConfigCluster._fetch_tls`](https://opendev.org/openstack/python-magnumclient/src/commit/cf374db1a93cc0fe8d326a61333837e3b7eeb0e9/magnumclient/osc/v1/clusters.py#L452), [`_config_cluster_kubernetes` et `generate_csr_and_key`](https://opendev.org/openstack/python-magnumclient/src/commit/cf374db1a93cc0fe8d326a61333837e3b7eeb0e9/magnumclient/common/utils.py#L210).
- `--use-keystone` prend la priorité si les deux options d’authentification sont présentes. Avec TLS actif, le client récupère la CA et écrit un bloc `exec` qui lit `OS_TOKEN` au moment où `kubectl` accède au cluster. Le fichier contient la CA et la commande, et l’accès dépend de la prise en charge de Keystone par le cluster. Avec `tls_disabled`, le chemin Kubernetes écrit une configuration sans données TLS et sans bloc `exec`. [`ConfigCluster.take_action`](https://opendev.org/openstack/python-magnumclient/src/commit/cf374db1a93cc0fe8d326a61333837e3b7eeb0e9/magnumclient/osc/v1/clusters.py#L417), [génération du kubeconfig](https://opendev.org/openstack/python-magnumclient/src/commit/cf374db1a93cc0fe8d326a61333837e3b7eeb0e9/magnumclient/common/utils.py#L210), [guide Magnum sur l’authentification Kubernetes par Keystone](https://docs.openstack.org/magnum/latest/user/index.html#keystone-authentication-and-authorization-for-kubernetes).
- `--dir` désigne le répertoire local, avec `.` par défaut. `--output-certs` écrit aussi les fichiers `ca.pem`, `cert.pem` et `key.pem` selon les données disponibles. Le kubeconfig en mode certificat garde les données intégrées. `--force` permet l’écrasement. La sortie standard fournit l’instruction de shell qui pointe `KUBECONFIG` vers le fichier `config`. Si l’adresse API manque, la commande émet un avertissement puis poursuit son chemin. Le code client conserve aussi un chemin historique Swarm qui imprime des variables Docker. [`ConfigCluster`](https://opendev.org/openstack/python-magnumclient/src/commit/cf374db1a93cc0fe8d326a61333837e3b7eeb0e9/magnumclient/osc/v1/clusters.py#L376), [`config_cluster`](https://opendev.org/openstack/python-magnumclient/src/commit/cf374db1a93cc0fe8d326a61333837e3b7eeb0e9/magnumclient/common/utils.py#L197).
- La CA publique permet au client de vérifier le serveur. Magnum conserve les clés de signature des CA via son gestionnaire de certificats et renvoie du PEM public ou signé. Une paire de clés Nova sélectionnée dans le formulaire Skyline concerne l’accès SSH aux machines. [`generate_certificates_to_cluster` et `sign_node_certificate`](https://opendev.org/openstack/magnum/src/commit/68befbf84e8ec50e57dee682cea9398bba606904/magnum/conductor/handlers/common/cert_manager.py#L90), [formulaire des nœuds Skyline](https://github.com/armeldemarsac92/skyline-console/blob/5a8ca40e86cbcbacf725b38fc14ca5acbed1e19a/src/pages/container-infra/containers/ClusterTemplates/actions/StepCreate/StepNodeSpec/index.jsx#L182).

Les règles amont de certificat sont de portée projet et reçoivent `cluster.as_dict()` comme cible. `certificate:get` autorise l’administrateur ou le lecteur du projet dont l’identité correspond au `user_id` enregistré sur le cluster. `certificate:create` autorise l’administrateur ou le membre du projet qui correspond à ce même `user_id`. `certificate:rotate_ca` permet aussi à un autre membre de ce projet de demander la rotation. `cluster config` cumule ces contrôles avec les lectures du cluster et de son modèle selon le mode choisi. Le fichier de politique du cloud peut modifier ces droits. [Règles `certificate:*`](https://opendev.org/openstack/magnum/src/commit/68befbf84e8ec50e57dee682cea9398bba606904/magnum/common/policies/certificate.py#L19), [règles de base Magnum](https://opendev.org/openstack/magnum/src/commit/68befbf84e8ec50e57dee682cea9398bba606904/magnum/common/policies/base.py#L75), [politique officielle](https://docs.openstack.org/magnum/latest/configuration/sample-policy.html). Voir aussi les [opérations sur la CA](04b-certificats.md).
