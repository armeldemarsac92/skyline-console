# Présenter les actions autorisées dans Skyline

Les règles par défaut distinguent la lecture du projet, les mutations par un membre et certaines opérations administratives. Dans Skyline, `policyMap.magnum` associe seulement `cluster:` et `clustertemplate:` à Magnum. Avec une liste de politiques chargée, `checkPolicyRule` renvoie `true` quand une règle recherchée est absente. Pour proposer « Créer un groupe », vérifier que la règle évaluée est bien `magnum:nodegroup:create` et disponible via Skyline. Une réponse 403 du service doit rester visible même si l’interface avait présenté l’action. [Résolution des règles Skyline](https://github.com/armeldemarsac92/skyline-console/blob/5a8ca40e86cbcbacf725b38fc14ca5acbed1e19a/src/resources/skyline/policy.js) · [Règles nodegroup](https://opendev.org/openstack/magnum/src/commit/68befbf84e8ec50e57dee682cea9398bba606904/magnum/common/policies/nodegroup.py)

L’API Skyline stable 2026.2 calcule les décisions pour le profil connecté et publie les règles sous la forme `magnum:nodegroup:create`. Son registre inclut les groupes, les quotas, les statistiques et les certificats. Il omet `credential:rotate`. Pour cette opération, la console peut présenter la confirmation au membre du projet selon la règle Hibiscus lorsque le registre est incomplet, puis rendre la décision effective de Magnum. Une décision explicite de refus dans Skyline reste prioritaire.
