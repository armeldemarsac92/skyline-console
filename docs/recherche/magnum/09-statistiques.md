# Compter les clusters et les nœuds d’un projet

`openstack coe stats list PROJET` interroge `GET /v1/stats?project_id={project_id}`. La réponse porte deux compteurs, `clusters` et `nodes`. Le serveur compte les clusters enregistrés et somme les `node_count` des groupes, plan de contrôle compris. Ce nombre ne mesure donc pas les nœuds Kubernetes en état `Ready`. [Commande OSC](https://opendev.org/openstack/python-magnumclient/src/commit/cf374db1a93cc0fe8d326a61333837e3b7eeb0e9/magnumclient/osc/v1/stats.py) · [Calcul SQL Magnum, get_cluster_stats](https://opendev.org/openstack/magnum/src/commit/68befbf84e8ec50e57dee682cea9398bba606904/magnum/db/sqlalchemy/api.py#L221)

La CLI stable exige le projet en argument. L’API accepte aussi un appel sans `project_id` : le lecteur obtient son projet et l’administrateur peut obtenir le total global. Le seul type accepté est `cluster`. La règle par défaut est `stats:get_all`. [Contrôleur](https://opendev.org/openstack/magnum/src/commit/68befbf84e8ec50e57dee682cea9398bba606904/magnum/api/controllers/v1/stats.py) · [Politique](https://opendev.org/openstack/magnum/src/commit/68befbf84e8ec50e57dee682cea9398bba606904/magnum/common/policies/stats.py) · [Référence CLI](https://docs.openstack.org/python-openstackclient/2026.2/cli/plugin-commands/magnum.html#coe-stats-list)

Le client Magnum du fork ne déclare pas `stats`. Le nombre de clusters déjà présenté dans les quotas provient de la longueur d’une liste. Pour un futur compteur de nœuds par projet, l’API d’agrégation évite de charger chaque détail de cluster. Pour connaître les workers d’un pool donné, lire ses nodegroups.
